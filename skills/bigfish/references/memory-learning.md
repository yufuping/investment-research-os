# 投资记忆与学习规则

## 1. 记忆分层

- ChatGPT 记忆：投资风格、要求回报率和交互偏好；
- Bigfish Skill：稳定的投资方法、研究流程和判断纪律；
- Investment Research OS：正式的公司研究历史、论点、假设、预测、决策、估值和复盘。

不要把公司事实堆进 Skill，也不要用非结构化聊天记忆替代正式投资账本。

## 2. 论点账本

论点应版本化追加，不覆盖有复盘价值的历史状态。至少记录公司、创建时间、被替代论点、核心论点、支持证据、反面证据、置信度和状态。

更新研究时回答：哪些事实改变、哪些假设改变、置信度为什么改变、核心论点是否仍成立。

## 3. 假设账本

记录高影响假设及其置信度。每次更新检查：已确认、已证伪、置信度变化或新增。估值中的增长率、利润率、资本强度和期末倍数应能够追溯到明确假设。

## 4. 预测账本

只记录有意义且可证伪的预测。至少包含预测内容、预测日期、预计验证日期、置信度、实际结果、结果分类和错误原因。

到期后标记正确、错误或部分正确，并区分：信息缺失、模型错误、时间判断错误、概率误判或不可预见事件。

## 5. 决策日志

研究观点不等于真实投资行为。保存真实买入、卖出、加仓、减仓或仓位之前，必须有用户明确确认或明确陈述交易已经发生。

正式决策至少记录：日期、价格、仓位、要求回报、基准/悲观/乐观回报、核心论点、关键假设、主要风险、加仓条件、卖出条件和置信度。

## 6. 关键未知与跟踪变量

关键未知保存描述、影响、证据状态、置信度和解决结果。每家公司只保留少量真正决定论点的跟踪变量，使后续研究聚焦变化而不是重复全文。

## 7. 增量研究

首次研究建立基线。后续更新以旧论点和新信息为输入，输出：

- 新事实；
- 假设变化；
- 预测验证结果；
- 论点变化；
- 估值和预期回报变化；
- 新增或已解决的关键未知。

## 8. 公司讨论纪要

当用户说“总结我们的对话并保存”或提出同类要求时：

1. ChatGPT 只总结当前可见对话，不声称读取了不可见的其他会话；
2. 生成并展示：讨论标题、核心摘要、关键观点、观点变化、当前结论、未解决问题和后续跟踪事项；
3. 用户确认摘要准确后，调用 Investment Research OS 的 `save_discussion_summary`；
4. 默认保存提炼后的纪要，不保存原始聊天全文；
5. 纪要是独立记录，不自动升级为正式论点、研报、估值或真实交易；
6. 后续讨论前可调用 `get_discussion_history`，优先复核“与上次相比发生了什么变化”。

## 9. 正式研报的生成与保存

当用户要求生成并保存一份完整研报时，采用“前端生成、后端存储”流程：

1. 当前 ChatGPT 依照 Bigfish 方法、引用的证据和本轮讨论生成研报；Investment Research OS 后台不调用大模型重新生成。
2. 先在对话中展示完整研报，让用户修正数据、论点、风险排序和估值假设。
3. 只有用户明确说“确认保存”、“保存并定稿”或同等表述后，才能创建正式研报草稿。
4. 先调用 `create_report_draft`，再按正文顺序逐章调用 `append_report_section`。网络重试时对同一 `report_id + section_order` 重复写入，会更新该章而不会新增重复章节。
5. 所有章节写入后，调用 `finalize_research_report` 定稿。已定稿版本不得覆盖；后续修订必须新建版本，并保留上一版链接和变更摘要。
6. 读取时先用 `get_saved_report_history` 确认版本，再用 `get_saved_research_report`。若返回 `has_more=true`，必须按 `next_offset` 继续取完，不得把截断内容冒充全文。
7. 正式研报是某一时点的完整研究快照；讨论纪要是后续对话的提炼记录。两者可互相引用，但不互相覆盖，也不自动升级为真实交易。

## 10. 结果与过程

分别评价投资结果和决策过程：结果好不证明过程好，结果差也不自动证明过程差。复盘应判断原始证据、概率、估值和风险补偿是否合理。

## 11. 方法改进

研究中发现的通用方法问题可以保存为改进候选，包括问题、证据、建议变化和置信度。Bigfish 不得自行改写并发布生产 Skill。

升级流程必须经过：候选积累 → Codex 复核 → 去重与泛化判断 → 修改建议 → 测试或评估 → 展示差异 → 用户明确批准 → 发布 → 记录实施版本。
